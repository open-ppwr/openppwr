# Administrator operations draft

Administrators separate migration and runtime database identities, keep `FORCE RLS` enabled, store bearer/bootstrap credentials outside Git, and mount evidence storage privately. Production requires HTTPS, fail-closed malware scanning, backups, restore rehearsal, monitoring and immutable deployment artifacts.

Bootstrap is one-time and separately authenticated. Do not expose bootstrap credentials to the browser or retain them after onboarding. Validate `/health` without disclosing tenant state. `/health` and `/health/live` answer liveness only: the process is running, and no dependency is consulted, so neither ever answers "unhealthy" because of a database outage. Point availability monitoring and any container or orchestrator healthcheck at `/health/ready` instead, which returns `200` when the database answers through the connection pool and `503` with a reason code when it does not; a liveness answer cannot tell a working API apart from one whose pool is exhausted. Both new routes are served on the API container's own port and are not proxied to the public surface. Apply migrations before traffic; never perform destructive down-migrations. See the deployment and recovery documents for blocked validation status.

Monitor evidence jobs by status and age without reading evidence content. After scanner/storage remediation, a tenant administrator may requeue a `dead` job through `POST /v1/scan-jobs/{jobId}/requeue`; the route resets attempts and records previous failure metadata in tenant audit history. Never requeue with manual SQL or mark evidence clean manually. Scanner errors remain fail-closed, and only verified reviewer roles may accept evidence after a clean result. Worker shutdown is process-level rollback-safe because an interrupted in-flight transaction releases its job lock and preserves previous durable state.
